# Separate Display Profiles from application and runtime state

Display automation behavior is split into manually selected Display Profiles containing `automatic`, `polling`, and Rules, while the hotkey, display history, Active Profile selector, and boot-scoped recovery evidence remain application-wide. One canonical file and an independent last-known-good backup persist each Profile. This boundary keeps named office/home behavior reusable without duplicating mutable display identity or losing the recovery evidence that makes re-enabling app-disabled displays safe; a monolithic multi-Profile document was rejected because one invalid or interrupted write would couple every Profile, and complete copies of the former `AppConfiguration` were rejected because aliases, history, hotkey registration, and runtime ownership do not vary by Profile.
